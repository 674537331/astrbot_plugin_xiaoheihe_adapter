# v1.3.4 维护审查与功能取舍

审查日期：2026-11-06。基线：主干 `90d3c9d`（v1.3.3）与 PR #32 `0d4f8ba`。

## 方案与结论

先核对 PR 的接口变更和证据，再检查项目的接入、Agent、存储、页面及发布链路；以兼容修复版 v1.3.4 交付。当前不需要整体重构，也不需要复制一套独立聊天/模型客户端。优先修复评论写入契约、请求签名时机、发送结果核对和维护检查。

## PR #32

- 修复目标明确：既有评论 POST 缺少网页 `_rnd` 签名，返回“缺失参数”。
- 保留贡献者的原始提交；网页写参数通过端点标记隔离，读取契约没有一起改写。
- 固定向量、完整写参数形状、随后读取不受污染和错误发送不重复 POST 均有回归验证。
- PR 贡献者记录了真实账号的参数对照及发送成功；本轮没有维护者账号的真实发送测试。
- PR 的原始 Actions 停在首次贡献者审批；本轮将同一原始提交及维护改动放在仓库自有分支运行 CI，不修改分支保护或首次贡献者审批策略。

## 后续优先级

1. **下一次明确功能需求前保持现有架构。** 评论写入恢复与发送核对安全性优先于扩大平台写入范围。
2. **按独立维护需求逐步拆分 `main.py`。** 当前入口约 3,300 行，图片准备、视觉缓存与上下文注入可逐步提取为服务。入口钩子和对外接口先保持稳定，拆分需补契约测试；这不是本次修复的发布前提。
3. **生图评论作为独立后续功能。** 先明确宿主图片输出格式、官方上传权限、大小/格式校验、公开图片说明和状态未知补偿，再做端到端验证。不能仅添加 `imgs` 字段就宣称支持。
4. **发帖、每日任务及 App 登录暂不加入。** 这些能力与当前原生讨论适配器的职责差异较大，且暂无本项目真实账号验证。

## 验证与升级

完整验证步骤、覆盖率口径和限制见 [测试说明](testing.md)；评论协议与验证来源见 [API 契约](xiaoheihe-api-contract.md)。v1.3.4 不增加配置、运行依赖或数据库迁移，更新插件并重载即可使用。原有 `dry_run` 与人工审核设置继续有效。

本版修复不会批量重发旧失败评论；已明确失败或状态未知的事件继续受发送闸门保护。部署后应通过新的测试通知或新审核候选验收，不要直接重放旧记录。
